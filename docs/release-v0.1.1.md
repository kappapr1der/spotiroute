Исправлена установка при существующей нерабочей записи Spotify в `hosts`.

В 0.1.0 установщик подхватывал адрес из `hosts`, но исходный адрес из комплекта исчезал из списка запасных кандидатов. Если DNS не давал доступной замены, установка останавливалась. В 0.1.1 исходный вариант сохраняется и проверяется перед применением. Непроверенный адрес по-прежнему не записывается.

При отказе сохраняется `data\setup-result.json`. Сообщение указывает неответившие имена, а «Открыть журнал» показывает отчёт даже после незавершённой установки. В `bootstrap\status.json` сохраняются и результаты проверок кандидатов. Устаревший системный curl теперь получает отдельную ошибку.

Для повторной попытки после ошибки 0.1.0 скачайте новый `SpotiRoute.exe` и нажмите «Установить компонент». Удалять `hosts`, папку данных или резервные копии не требуется. Уже работающий фоновый компонент эта версия автоматически не заменяет.

Проверено: 60 тестов на Windows PowerShell 5.1, сборка EXE и вложенные файлы. Отдельная сетевая проверка на Windows 11 с начальным адресом `143.20.64.192` выбрала `199.232.210.250` после проверки двух разных обложек по HTTPS; действующий `hosts` в этой проверке не менялся.

Проверка на сети другого пользователя всё ещё требуется: исправление сохраняет дополнительные варианты для проверки, но не гарантирует доступность шлюза или CDN у каждого провайдера. Выпуск остаётся beta.
