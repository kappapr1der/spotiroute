# SpotiRoute

Утилита для Windows, которая проверяет адреса Spotify в `hosts` и подбирает замену, когда перестают загружаться обложки или теряется соединение сервисов Spotify, используемых Discord и Spotify Connect.

**[Скачать SpotiRoute 0.1.1 beta](https://github.com/kappapr1der/spotiroute/releases/tag/v0.1.1)**

## Запуск

1. Скачайте `SpotiRoute.exe` из раздела Releases и откройте его.
2. Нажмите «Установить компонент». Windows запросит права администратора для записи в `hosts` и создания фоновой задачи.
3. После установки окно можно закрыть: задача продолжит проверку каждые две минуты, включая запуск после перезагрузки Windows.

В окне доступны ручная проверка, пауза, журнал, возврат прежних адресов и удаление фоновой задачи. Возврат адресов отключает проверку и восстанавливает только семь записей Spotify к состоянию до установки. Удаление задачи сохраняет текущие адреса и резервные копии; при необходимости сначала выполните возврат адресов.

Требуются Windows 10/11, .NET Framework 4.8, Windows PowerShell 5.1 и системный `curl.exe` с поддержкой `%{json}` (7.70 или новее). Первая beta проверена на Windows 11. EXE не подписан цифровым сертификатом; Windows может показывать сведения о неизвестном издателе.

## Как меняются адреса

Рабочий адрес сохраняется, даже если DNS уже предлагает другой. Замена допускается после двух неудачных циклов и проверки нового адреса. При полном обрыве сети или отсутствии подходящей замены остаются последние адреса.

Для обложек кандидаты получаются через DNS over HTTPS Cloudflare и Google. Проверяются TLS-сертификат, HTTP-ответ и два разных JPEG-файла. Для управляющих сервисов используются адреса, опубликованные в [списке AstraCat](https://github.com/ASTRACAT2022/host-DNS/blob/main/base_hosts.txt): общий шлюз определяется по совпадению нескольких записей, затем проверяются все пять имён Spotify. Эти пять записей переключаются вместе. Список кандидатов обновляется раз в 30 минут и при повторном сбое.

Адреса из комплекта сохраняются как запасные кандидаты, даже если при установке найдена другая запись Spotify в `hosts`. Они проходят те же проверки перед применением. Поэтому существующая нерабочая запись не лишает установщик исходных вариантов для проверки.

| Назначение | Имена |
| --- | --- |
| Обложки | `i.scdn.co`, `image-cdn-ak.spotifycdn.com` |
| Управляющие сервисы | `api.spotify.com`, `dealer.spotify.com`, `spclient.wg.spotify.com`, `gew1-spclient.spotify.com`, `gew1-dealer.spotify.com` |

Изменения ограничены этими семью именами. Перед записью создаётся резервная копия, а параллельное изменение `hosts` отменяет запись. Строки, в которых Spotify и посторонний домен записаны вместе, требуют ручного разделения: программа их не переписывает.

Утилита обращается к DNS-провайдерам, CDN Spotify, GitHub и шлюзу AstraCat. Управляющий трафик Spotify направляется через сторонний шлюз AstraCat; его доступность и правила могут меняться. Работа зависит от провайдера и других сетевых программ на компьютере. Активные профили Zapret, которые повторно записывают эти же имена в `hosts`, нужно отключить отдельно.

Состояние «маршрут доступен» подтверждает сетевую проверку. Оно не проверяет фактическое название трека в Discord, авторизацию или доступность альбома для аккаунта. Программа не читает токены, не связывает аккаунты и не перезапускает приложения.

## Файлы и фоновая задача

Внутреннее имя задачи — `Spotify Network Guard`, папка — `C:\ProgramData\SpotifyNetworkGuard`. Эти имена сохранены для совместимости с первоначальной установкой. Задача выполняется от SYSTEM, с ограничением времени и без одновременных запусков. Изменять её скрипты могут только администраторы и SYSTEM.

В `data` находятся `status.json`, `state.json`, журнал `events.jsonl` и резервные копии. Журнал ограничен по размеру, сохраняются до 20 рабочих копий. Отдельно остаётся первоначальная копия `hosts`. **Не публикуйте резервные копии целиком:** они могут содержать ваши личные сетевые настройки.

Если установка остановилась на проверке сети, повторите её новым EXE. При повторном отказе кнопка «Открыть журнал» покажет `data\setup-result.json`; подробные пробы остаются в `data\bootstrap\status.json`. В них указаны неответившие имена и результаты проверки запасных адресов. Такой отказ происходит до первой записи в `hosts`. В версии 0.1.1 также отдельно проверяется версия системного curl, чтобы отсутствие поддержки JSON не выглядело как недоступность всех адресов.

## Проверка входа в аккаунт

Если Spotify показывает accesspoint:37, доступны отдельные архивы для сбора отчёта: [серверы входа и сводка прокси](https://github.com/kappapr1der/spotiroute/releases/download/v0.1.1/SpotiRoute-Desktop-Diagnostics-0.1.1.zip) и [начальный обмен с access point](https://github.com/kappapr1der/spotiroute/releases/download/v0.1.1/SpotiRoute-AccessPoint-Diagnostics-0.1.1.zip). Второй нужен, когда HTTPS уже отвечает, а ошибка входа остаётся. Инструкция находится внутри каждого архива.

Проверки сохраняют отчёты локально, не меняют настройки и не выполняют вход в аккаунт. Доступность проверяемых серверов не подтверждает успешную авторизацию Spotify.

## Сборка из исходников

Зависимости NuGet не требуются. Используется компилятор C# из .NET Framework.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Guard.ps1 -PackageRoot .\scripts
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\package.ps1
```

Сборка появляется в `artifacts`, архив для выпуска — в `dist`. Проверка вложенных файлов без установки:

```powershell
Start-Process .\artifacts\SpotiRoute.exe -ArgumentList '--self-test artifacts\self-test.json' -Wait
Get-Content .\artifacts\self-test.json
```

В тестах проверяются выбор замены, сохранение посторонних строк, резервное копирование, конфликт записи и откат при отсутствовавших до установки записях. Установленная фоновая задача проверена реальным запуском на Windows 11; поиск замены проверен отдельно без изменения рабочих адресов. **Полный цикл установки и удаления на чистой виртуальной машине пока не проверен.** Поэтому выпуск помечен как beta.
