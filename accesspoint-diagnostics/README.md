# Проверка протокола access point

Для случая, когда HTTPS-проверки проходят, а Spotify продолжает показывать accesspoint:37.

Распакуйте архив, оставьте Spotify на экране ошибки и сохраните работающую стратегию Zapret. Запустите Run-AccessPoint-Diagnostics.cmd. Через 1–2 минуты рядом появится SpotiRoute-AccessPoint-Diagnostics.json — передайте этот файл для разбора.

Проверка получает публичный список access point у Spotify и отправляет начальный ClientHello на первые шесть адресов из списка и резервный ap.spotify.com:443. В ответе проверяется подпись сервера Spotify. Открытый TCP-порт сам по себе успешной проверкой протокола не считается.

ServerSignatureVerified:true означает, что получен и проверен подписанный начальный ответ сервера. Обмен ключами не завершается, вход в аккаунт не выполняется. Успех этой пробы не подтверждает исправность авторизации или официального приложения. Пробы идут отдельным процессом; правила брандмауэра для Spotify.exe могут действовать иначе.

Права администратора не нужны. Скрипт не читает prefs, журналы, пароли или токены. Hosts, DNS, службы и настройки приложений не изменяются. Отчёт сохраняется локально, автоматической отправки нет. Системный curl должен поддерживать JSON (7.70 или новее); TLS-проверка HTTPS включена.

В отчёт попадают только публичные адреса серверов, результаты проверок, число процессов Spotify и winws/winws2, время и признак сохранности hosts.

Описание протокола и публичный ключ сверены с librespot, commit 99b6088bf3ea028f90192676ac1a337fa4b2ed12:
- https://github.com/librespot-org/librespot/blob/99b6088bf3ea028f90192676ac1a337fa4b2ed12/core/src/connection/handshake.rs
- https://github.com/librespot-org/librespot/blob/99b6088bf3ea028f90192676ac1a337fa4b2ed12/protocol/proto/keyexchange.proto

SpotiRoute использует собственную реализацию этой диагностической пробы. Протокольная версия ClientHello соответствует reference-клиенту librespot; это не версия установленного Spotify.
