# Проверка входа в Spotify

Для случая, когда SpotiRoute показывает доступные маршруты, но Spotify не пускает в аккаунт или выдаёт `accesspoint:37`.

Распакуйте архив, оставьте Spotify на экране входа/ошибки, сохраните текущее состояние Zapret и запустите `Run-Desktop-Diagnostics.cmd`. Через 1–2 минуты рядом появится `SpotiRoute-Desktop-Diagnostics.json` — передайте этот файл для разбора.

Проверка читает версию Spotify и только сводку прокси из найденных файлов `prefs`: числовой режим и признак заданного адреса. Пароль, логин, адрес прокси, полный путь к файлу и прочее содержимое `prefs` в отчёт не попадают. Полный файл настроек не копируется и не отправляется.

Утилита выполняет запросы без авторизации к `apresolve.spotify.com`, `login5.spotify.com`, `clienttoken.spotify.com`, `accounts.spotify.com`: сравнивает текущий DNS/hosts и шлюз AstraCat, который уже используется SpotiRoute. Ответы 405 на GET к серверу входа возможны: это проверка транспорта, а не попытка авторизации. Дополнительно проверяется TCP-доступность двух адресов из ответа AP resolver.

Права администратора не требуются. Настройки, hosts, DNS и службы не изменяются, Spotify не закрывается. Вход в аккаунт от имени пользователя не выполняется. Отчёт сохраняется локально; автоматической отправки нет.

Используемые сетевые адреса видны в открытом коде [AP resolver](https://github.com/librespot-org/librespot/blob/dev/core/src/apresolve.rs) и [Login5](https://github.com/librespot-org/librespot/blob/dev/core/src/login5.rs) клиента librespot. Это технические проверки соединения; успешный HTTP-ответ не подтверждает успешный вход в Spotify.
